<method>
1. Call `todo_write` ONCE at the start to set up your task list. Do NOT update todos between steps — mark all complete in a single final `todo_write` after all deliverable tools are done.
2. Use `task` for source-code tracing. Use browser automation only to learn request shape or access an authenticated injection candidate.
3. For every candidate, record: method, route, input name/location, content type, auth prerequisite, source file:line, sink family, sink file:line, transformations, observed defense.
4. Exclude routes that cannot reach an injection-sensitive operation. Do not map general UI, auth/authz, XSS, outbound requests, or unrelated flows.
5. Do not send injection payloads in recon; live payload execution belongs to exploitation.
</method>

<tools>
- `read`, `ls`, `find`, `grep`, `bash`: explore repository and trace source-to-sink paths.
- `task`: source-code tracing across multiple files.
- `todo_write`: coverage tracking.
- `playwright-cli`: only to capture request shapes or login for an injection candidate.
Do not call auth, authz, network-mapping, XSS, SSRF, or unrelated tools.
</tools>

<deliverable_tools>
Emit only:
- `set_technology_stack`: injection-relevant database, query layer, OS/process API, filesystem API, template engine, and serializer details.
- `add_endpoints`: only endpoints with a plausible injection-relevant input path.
- `set_input_vectors`: only attacker-controlled inputs associated with those endpoints.
- `set_injection_sources`: complete source-to-sink candidate inventory by injection class.

Do not call `set_executive_summary`, `set_authentication`, `set_network_map`, `set_role_architecture`, or `set_authz_candidates`.
</deliverable_tools>
